# pi のセッション保存パスをホストの絶対パスに合わせる

## 状況

ai-env はホストの `~/.pi` をコンテナの `/home/pi/.pi` にマウントしている。
そのため、コンテナ内で pi が子セッションを作成すると、セッションヘッダーの
`parentSession` に `/home/pi/.pi/agent/sessions/...` が保存される。

一方、ホストの ctx は同じファイルを `/Users/<ユーザー>/.pi/agent/sessions` から
読み込む。ctx 1.0 以降は `parentSession` を実際に解決してセッション系譜を検証するため、
コンテナ側の絶対パスをホスト側で解決できず、Pi のソース全体が `invalid capture` に
なることがある。

## 判断

セッションファイルについてだけ、ホストの絶対パスをコンテナ内でも有効にする。

- `PI_CODING_AGENT_SESSION_DIR` にホストの
  `~/.pi/agent/sessions` を設定する
- 同じホストディレクトリを、同じ絶対パスへ追加でマウントする
- 既存の `/home/pi/.pi` マウントは設定・拡張機能の互換性のため維持する
- `/workspace/<project>` の cwd は従来どおりコンテナ内パスを使う。cwd のホストパス化は行わない

これにより、pi が新しく作るセッションの `parentSession` はホストからも解決可能になる。

## 影響

- セッションディレクトリの二重マウントが発生するが、どちらも同じホスト資産を参照する
- 既に `/home/pi/.pi/...` を `parentSession` に持つ過去セッションは自動修正しない
- 過去セッションを ctx に取り込むには、pi を停止したうえで、ホスト側で
  `parentSession` の `/home/pi/.pi` プレフィックスをホストの `~/.pi` に置換する
- `parentSession` はセッションファイルの絶対パスであるため、ホストのホームディレクトリを
  コンテナへ固定値として焼き込まず、ai-env 起動時の `HOME` から動的に組み立てる

## 代替案

- **ctx のバージョンを古い版へ固定する**: lineage 検証を弱めるだけで、壊れたパスを残すため採用しない
- **セッションヘッダーを無視する**: 親子関係という pi の情報を失うため採用しない
- **`/home/pi/.pi` のみをホストパスへ変更する**: 拡張機能や既存のコンテナ内パスとの互換性を壊すため採用しない
