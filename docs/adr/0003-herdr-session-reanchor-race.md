# herdr 0.8.0 のセッション再アンカー競合への対処（agent_start パッチ + presence 待機）

herdr 0.8.0 では、フルライフサイクル統合（pi 等）の状態報告が「Agent Presence（サーバーがペインでエージェントを検出している状態）」の確立を前提とする。コンテナ再起動直後はサーバーのプロセス検出が追いつかず、pi の session_start 報告（`pane.report_agent_session`）が無視されることがある。このときサーバーのセッション参照が旧セッションに固定されたまま現在セッションの状態報告が全て拒否され、サイドバーが更新されなくなる（2026-08-10 実測・再現確認済み）。

対策は 2 つ（コンテナ起動スクリプトに組み込み）:

- **agent_start パッチ**: herdr 管理の `herdr-agent-state.ts` の agent_start 内 `reportSession()` に認識済み reason（`"resume"`）を付与する。統合バージョン v8 のときのみ sed で適用し、パッチ済みならスキップ（冪等）。毎ターンのセッション報告が再アンカーとなり、presence 確立後の最初のターンで自己修復する。
- **presence 待機**: pi 起動前に `herdr agent explain` が成功するまで最大 10 秒待つ（resume / default モードのみ）。起動直後のレースを根本的に回避する。確立しなくても pi の起動自体は続行する（パッチが補完）。

意図的な判断:

- **別拡張での再送は採用しない**: 再送用拡張の seq は公式拡張と同じ source（`herdr:pi`）の水位（`hook_report_sequences`）を共有するため、再送報告が公式拡張の状態報告を弾いてしまう競合を避けられない。同一ファイルへの最小パッチ（同一 seq ストリーム）が安全。
- **herdr 本体への issue 報告はしない**: AI による issue 報告は現時点では控える方針。upstream が将来修正すれば本パッチは不要になる（バージョンガード付きのため、統合更新時は自動的に適用対象外になる）。
