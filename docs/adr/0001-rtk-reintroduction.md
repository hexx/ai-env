# RTK の再導入

PR #105 で削除した RTK（rtk-ai/rtk）をサンドボックスに再導入する。削除理由は、rtk の出力圧縮・コマンド書き換えが pull-request スキル実行時の AI を混乱させたためで、同スキルの頑健化により解消したと判断した。目的はトークンコスト低減。拡張機能は手書きせず rtk 公式の pi 連携（`rtk init -g --agent pi`）を使い、コンテナ起動時にインストールする（`~/.pi` はホストマウントのためイメージ焼き込みは無効化される）。

意図的に維持・採用した判断（将来「改善」で壊さないこと）:

- **インストールは master の install.sh を curl 実行（バージョン無固定）**。Dockerfile が herdr に対して指摘しているのと同種のサプライチェーンリスクを、今回は認識した上で受け入れている（rtk の更新が速く、最新版のフィルタ改善を追いたい）。
- **マウント二段構成**（ホスト `~/.config/rtk` → コンテナ `/home/pi/.rtk` ＋起動時 symlink）は、`/home/pi/.config/rtk` への直接マウントに簡略化しない。過去にこの周辺でトラブルがあり（詳細は失念、commit `6c205ec` 周辺）、再現性を優先した。
- ホスト側 `~/.config/rtk` の事前作成はしない（ディレクトリ存在を前提とする既知の制約）。
