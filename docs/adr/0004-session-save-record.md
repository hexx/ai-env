# セッション保存は共有 `~/.pi` 経由の保存記録でホスト側が同期する

Status: superseded by ADR-0005

コンテナ内 pi からホストの `~/.config/ai-env/pi-projects.json` を更新する保存機能（`/save-session`）の伝達経路として、
マウント追加による直接書き換えや HTTP サーバーではなく、ホストと共有済みの `~/.pi/ai-env/session-saves/` に
保存記録を書き出し、ホスト側 ai-env が次回起動時に pi-projects.json と同期する方式を採用した。

意図的な判断:

- **コンテナからの設定ファイル直接書き換えは採用しない**: `~/.config/ai-env` の新規マウントと JSONC のコメント保持更新ロジックをコンテナ側（pi 拡張機能）に載せることになり、テスト容易性が下がる。コメント付き JSONC の安全な書き換えはホスト側のテスト可能な Node.js 関数として実装する。
- **HTTP サーバーは採用しない**: 即時反映が得られるが、ホスト側の待受サーバー・ポート公開（`-p`）・Apple Container での動作確認が必要で、実装コストに対して効果が見合わない。
- **保存記録は削除せず常駐させる**: 適用後に削除すると「保存されたか分からない」という混乱を招く。1 プロジェクト 1 ファイルの常駐記録とし、ホスト側は値が一致していれば何もしない同期とする。これにより保存の可視性を保ち、コンテナ内 pi の `/resume-session`（保存済みセッションへの切り替え）も記録を直接参照できる。
- **同期の競合はタイムスタンプ比較で解決する**: 記録の `timestamp` と pi-projects.json の mtime を比較し、新しい方を優先する。ホスト側の手動編集を尊重しつつ、コンテナ内からの保存も確実に反映される。
- **非同期の受容**: pi-projects.json への反映は次回 `ai-env` 起動時になる。再開自体はコンテナ内 `/resume-session` で即時可能なため、実害は小さい。
