# 課題解決プロンプト: QWEN_TOKEN_PLAN_API_KEYをKeychainから取得して環境変数として渡す

## 1. 役割定義 (Persona)
あなたは高度なソフトウェアエンジニアおよび問題解決のエキスパートです。macOSのKeychain（キーチェーンアクセス）とシェルスクリプトに精通しており、セキュリティベストプラクティスを踏まえた実装を行えます。以下のコンテキストとゴールを基に、正確かつ効率的な修正/実装を行ってください。

## 2. 背景・前提条件 (Context)
- **現状発生している問題**:
  - `QWEN_TOKEN_PLAN_API_KEY` というAPIキーが、現状ではソースコード・設定ファイル・`.env`・CIシークレット等の中にベタ書き（または平文で配置）されている懸念がある。
  - このAPIキーは秘匿情報であり、リポジトリへのコミットや平文保存は避けたい。
  - ローカル環境（macOS）では、すでに macOS の Keychain に `QWEN_TOKEN_PLAN_API_KEY` というアカウント/サービス名で `security find-generic-password` により取得可能な状態で保存されている（あるいは保存する前提）。
- **再現手順（現状の問題を確認する手順）**:
  1. 該当スクリプト・Makefile・ドキュメント等を開き、`QWEN_TOKEN_PLAN_API_KEY` がどこに書かれているか確認する。
  2. `security find-generic-password -a QWEN_TOKEN_PLAN_API_KEY -w` を実行し、Keychainから取得できることを確認する。
  3. 実行時に `QWEN_TOKEN_PLAN_API_KEY` が未設定/不正で、API呼び出しが失敗することを確認する。
- **関連ファイル/コード（要探索）**:
  - リポジトリ直下および各サブディレクトリ配下の `Makefile`, `*.sh`, `*.zsh`, `*.bash`, `*.md`, `Dockerfile`, `docker-compose*.yml`, `package.json`, CI設定（`.github/workflows/*` 等）において `QWEN_TOKEN_PLAN_API_KEY` を `grep` し、対象箇所をリストアップすること。
  - シェル初期化ファイル（`~/.zshrc`, `~/.bashrc`, `~/.bash_profile` 等）も確認対象。
