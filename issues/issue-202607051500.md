# 課題解決プロンプト: ai-env起動時にホストの ~/.config/rtk/config.toml をコンテナへマウント

## 1. 役割定義 (Persona)
あなたは高度なソフトウェアエンジニアおよび問題解決のエキスパートです。以下のコンテキストとゴールを基に、正確かつ効率的な修正/実装を行ってください。

## 2. 背景・前提条件 (Context)
- **現状発生している問題**:
  `ai-env` でコンテナを起動した際、コンテナ内には `rtk` コマンドがインストール済み（Dockerfile で `curl https://raw.githubusercontent.com/rtk-ai/rtk/refs/heads/master/install.sh | sh` によりインストール）だが、ホストの `~/.config/rtk/config.toml` がコンテナに引き継がれない。このため、コンテナ内で `rtk` を使用する際にホスト側の設定（API キー、エンドポイントなど）が反映されず、毎回手動で設定する必要がある。

- **再現手順**:
  1. ホストの `~/.config/rtk/config.toml` に rtk の設定が存在することを確認する
  2. `ai-env` を実行してコンテナを起動する
  3. コンテナ内で `ls ~/.config/rtk/config.toml` を実行すると、ファイルが存在しない（またはデフォルトの空設定）

- **関連ファイル/コード**:
  - `/workspace/index-helpers.ts` — `buildVolumeArgs()` 関数（L169-173）でコンテナのボリュームマウントを定義している。ここに `~/.config/rtk/config.toml` のマウントを追加する必要がある
  - `/workspace/Dockerfile` — コンテナイメージの定義。`rtk` は L81 でインストールされている
  - `/workspace/index-helpers.ts` — `prepareEnvironment()` 関数（L265-289）で `home` 変数（`$HOME`）を取得して `buildVolumeArgs` に渡している
  - `/workspace/index-helpers.test.ts` — 関連するテストファイル

- **現在のボリュームマウント**（`buildVolumeArgs` 関数、L169-173）:
  ```typescript
  export const buildVolumeArgs = (home: string): string[] => [
    `--volume=${process.cwd()}:${CONTAINER_WORKSPACE}`,
    `--volume=${home}/.ssh:${CONTAINER_SSH}:ro`,
    `--volume=${home}/.pi:${CONTAINER_PI_HOME}`,
  ];
  ```

## 3. 解決すべきゴール (Goal & Objective)
- [ ] `buildVolumeArgs` 関数に `~/.config/rtk` ディレクトリをコンテナの `/home/pi/.config/rtk` にマウントするエントリを追加する（マウント方式を推奨。コンテナ内での変更をホスト側にも反映できるため）
- [ ] コンテナ内のマウント先パス `/home/pi/.config/rtk` を定数として定義する
- [ ] マウントは読み書き可能（`rw`、デフォルトで十分）とする（rtk がコンテナ内で設定を更新する可能性を考慮）
- [ ] ホスト側に `~/.config/rtk/config.toml` が存在しない場合でもエラーにならないようにする（ディレクトリが存在しない場合はスキップする or 警告を出すなどのフォールバック対応）
- [ ] 既存のテスト（`index-helpers.test.ts`）を確認し、必要に応じてテストを追加・修正する
- [ ] 既存の動作（他のボリュームマウント、環境変数注入など）を壊さないこと

## 4. 期待する成果物 (Output Format)
- `index-helpers.ts` の `buildVolumeArgs` 関数の修正（`~/.config/rtk` マウントの追加）
- 必要に応じた定数の追加（`CONTAINER_RTK_CONFIG` など）
- 修正理由とアプローチの簡潔な解説
- 動作確認またはテストの実行結果（`npm test` の通過確認）
