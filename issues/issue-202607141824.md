# 課題解決プロンプト: brave-search 拡張機能を pi-work プロファイル時のみ有効化する

## 1. 役割定義 (Persona)
あなたは高度なソフトウェアエンジニアおよび pi coding agent の拡張機能(Extensions)と
コンテナ起動ランチャー(ai-env)に精通したエキスパートです。以下のコンテキストとゴールを
基に、正確かつ最小リスクで修正/実装を行ってください。

## 2. 背景・前提条件 (Context)
- **現状発生している問題**:
  `/home/pi/.pi/agent/extensions/brave-search.ts` は **グローバル拡張機能** であり、
  `~/.pi/agent/extensions/*.ts` 配置のため `pi-work` と `pi-private` の両プロファイル
  （全プロジェクト）に無条件で適用される。
  現在この拡張機能は `pi.registerTool({ name: "brave_search", ... })` を条件なしで実行し、
  `session_start` でも通知を行っているため、`pi-private` 環境でも Brave Search ツールが
  有効になってしまっている。ユーザーは **`pi-work` のときだけ有効にしたい**。
- **再現手順**:
  1. `pi-private` プロファイルの pi セッションを起動する。
  2. ツール一覧（または `brave_search` の呼び出し可否）を確認する。
  3. 現在はツールが登録されている（有効）。これを `pi-work` でのみ有効にする。
- **関連ファイル/コード**:
  - `/home/pi/.pi/agent/extensions/brave-search.ts`
    - 拡張機能のエントリ。末尾の `export default function (pi: ExtensionAPI)` 内で
      `pi.on("session_start", ...)` と `pi.registerTool({ name: "brave_search", ... })`
      を無条件実行している。ここをプロファイルでゲートする。
  - `/workspace/index-helpers.ts`
    - `detectProfileName(cwd, profiles)`: ホスト側で cwd パスセグメントから
      `pi-work` / `pi-private` を判定する（例: `/Users/.../pi-work/doc-write-work`）。
    - `buildEnvArgs(params)`: コンテナ起動時に渡す環境変数を組み立てる。
      **現在は `LLM_API_KEY`, `OCR_*`, `GH_TOKEN`, `OPENCODE_API_KEY` などの固定リスト**
      しかコンテナへ渡さず、**プロファイル名を示す環境変数は渡していない**。
      呼び出し側（約 L421 付近）では `profileName = detectProfileName(...)` が
      取得済みであり、`profile` として `aiEnvConfig.profiles[profileName]` を渡しているため、
      ここで `profileName` を `buildEnvArgs` へ渡す拡張が可能。
  - `/workspace/pi-projects.example.json`（参考）
    - `profiles.pi-work` は `apiKeyEnv: "WORK_API_KEY"`, `provider: "anthropic"` 等を指定。
    - `profiles.pi-private` は `apiKeyEnv` 未指定（デフォルトで `LLM_API_KEY` 相当）。
- **補足（重要）**:
  - コンテナ内（拡張機能実行時）には「今どのプロファイルか」を示す環境変数が無いため、
    拡張機能だけでプロファイルを確実に判別するには、**ランチャー側からのプロファイル名
    環境変数の注入が必要** である（下記 Goal の推奨案）。
  - 現在のツール実装は API キーに `process.env.LLM_API_KEY` を使っている。
    `pi-work` ではプロファイルの `apiKeyEnv` が `WORK_API_KEY` である点に注意し、
    `pi-work` 時も Brave Search が正しく動作するようキー取得元を検討すること
    （`WORK_API_KEY` を見るようにする、または既存通り `LLM_API_KEY` で十分ならそのまま）。

## 3. 解決すべきゴール (Goal & Objective)
- [ ] **推奨アプローチ（確定的な判定）**:
  `/workspace/index-helpers.ts` の `buildEnvArgs` にプロファイル名を渡し、
  `--env=AI_ENV_PROFILE=<pi-work|pi-private>` のようにコンテナへ注入する。
  その上で `brave-search.ts` 側で `process.env.AI_ENV_PROFILE === "pi-work"` のときのみ
  `registerTool` / `session_start` 通知を行う（非 pi-work では何も登録しない/早期 return）。
- [ ] **代替アプローチ（最小変更・ヒューリスティック）**:
  ランチャー変更を避けたい場合は、`pi-work` では `apiKeyEnv=WORK_API_KEY` であるため、
  拡張機能側で `process.env.WORK_API_KEY` の存在で判定してもおおむね動作する。
  （`buildEnvArgs` は `WORK_API_KEY` を固定リストに含めていないため、ホスト側で
  `$WORK_API_KEY` が環境に展開されている `pi-work` コンテナ限定の挙動に依存する点に留意）
- [ ] `pi-work` 以外（`pi-private` など）では `brave_search` ツールが **登録されない**
      （ツール一覧に出ず、呼び出せない）ことを確認する。
- [ ] `pi-work` では引き続き `brave_search` が **正常に動作する** ことを確認する。
- [ ] 既存の他拡張機能 (`rtk.ts`, `herdr-agent-state.ts`, `block-push-to-main.ts`) や
      pi の起動フローには影響を与えないこと。

## 4. 期待する成果物 (Output Format)
- 修正が完了した `brave-search.ts`（および推奨アプローチを採る場合は `index-helpers.ts`）
- 修正理由とアプローチの簡潔な解説（どの環境変数で判定したか、非 pi-work 時の振る舞い含む）
- 動作確認結果:
  - `pi-work` コンテキストで pi を起動し `brave_search` が利用可能であること
  - `pi-private` コンテキストで pi を起動し `brave_search` が利用不可であること

## 6. 実行・検証記録 (2026-07-14)

### 実施内容
- **`/workspace/index-helpers.ts`**: プロファイル名をコンテナへ注入するよう改修。
  - `RunContext` インターフェースに `profileName: string` を追加。
  - `buildEnvArgs` の引数に `profileName: string` を追加し、戻り値の env リストに
    `--env=AI_ENV_PROFILE=${params.profileName}` を追加。
  - `prepareEnvironment` の戻り値に `profileName`（既に `detectProfileName` で算出済み）を設定。
  - `runContainerCommand` から `buildEnvArgs` へ `profileName: ctx.profileName` を渡すよう接続。
- **`/home/pi/.pi/agent/extensions/brave-search.ts`**: エントリ関数の冒頭で
  `if (process.env.AI_ENV_PROFILE !== "pi-work") return;` を追加。
  `pi-work` 以外（pi-private 等）では `session_start` ハンドラも `registerTool` も
  実行されず、ツールが登録されない。API キー取得元は既存の `LLM_API_KEY` のまま
  （`buildEnvArgs` は `LLM_API_KEY` を常に注入するため pi-work でも動作する）。
- **`/workspace/index.test.ts`**: `buildEnvArgs` の全呼び出しに `profileName` を追加、
  env 引数数の期待値を 13 → 14 に更新、新たに `AI_ENV_PROFILE` 注入を検証するテストを追加。
