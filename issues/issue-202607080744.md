# 課題解決プロンプト: HERDR_SOCKET通信を socat+pm2 から container run --publish-socket に移行

## 1. 役割定義 (Persona)
あなたは高度なソフトウェアエンジニアおよび Apple container / Linux コンテナ運用のエキスパートです。以下のコンテキストとゴールを基に、正確かつ効率的な修正/実装を行ってください。

## 2. 背景・前提条件 (Context)
- **現状の構成**:
  - コンテナ起動時の初期化スクリプト (`templates/common.sh.template`) 内で、`pm2` を使って `socat` を常駐プロセスとして起動している。
  - `socat` はコンテナ内の Unix ドメインソケット (`/home/pi/.config/herdr/herdr.sock`) への接続を、ホスト側の TCP ポート (`${HOST_IP}:9123`) に中継（ブリッジ）している。
  - これにより、コンテナ内のツール群が `herdr.sock` 経由でホスト側のサービス（herdr デーモン）と通信している。
  - 関連ファイル: `templates/common.sh.template`, `pi-script.ts`（`buildInitScript` 関数）
- **問題点**:
  - TCP ポート (`${HOST_IP}:9123`) 経由の中継は、ネットワーク越しのオーバーヘッドやファイアウォールの影響を受ける可能性がある。
  - Apple container 環境では、`--publish-socket` オプションによってホスト（macOS）とゲスト（Linux VM）間で Unix ドメインソケットを直接透過的に共有できる（virtio-vsock によるカーネルレベルの中継）。
  - Docker Desktop では不可能だった「Mac と Linux 間の直接 Unix ソケット通信」が Apple container では実現可能である。
- **Apple container `--publish-socket` の仕組み**:
  1. `container run --publish-socket <host-path>:<container-path>` を指定すると、ホスト側とコンテナ側の両方に Unix ソケットファイルが作成される。
  2. 片方のソケットにデータが書き込まれると、Apple container デーモンが virtio-vsock を通じてもう片方のソケットへストリームデータをメモリ上で直接ブリッジする。
  3. ユーザーからは、まるで Mac と Linux コンテナが 1 つの Unix ソケットファイルを直接共有しているかのように透過的に扱える。

## 3. 解決すべきゴール (Goal & Objective)
- [ ] `templates/common.sh.template` から `pm2 start socat` による socat ブリッジの記述を削除する
- [ ] `--bash` モード、`--resume` モード、デフォルト起動モードのすべてで、コンテナ起動時に `--publish-socket` が適用されるようにする
- [ ] コンテナ起動側（`container run` を実行している箇所）に `--publish-socket <host-socket-path>:<container-socket-path>` オプションを追加する（例: `--publish-socket /path/on/host/herdr.sock:/home/pi/.config/herdr/herdr.sock`）
- [ ] `common.sh.template` 内の `mkdir -p ~/.config/herdr` は、`--publish-socket` 使用時もソケットファイルの置き場所として必要かどうかを判断し、適切に維持または削除する
- [ ] `HOST_IP` に依存する部分（`${HOST_IP}:9123`）が不要になるため、関連する HOST_IP 解決ロジックへの影響を確認し、不要なコードがあれば整理する
- [ ] 既存の `pi-resume` 関数やその他のコンテナ内動作に影響を与えないこと
- [ ] pm2 が `herdr-socat` 以外の用途で使われていないか確認し、不要であれば pm2 関連の依存も整理する

## 4. 期待する成果物 (Output Format)
- 修正が完了したテンプレートファイル（`templates/common.sh.template`）および関連する TypeScript ソース（`pi-script.ts` またはコンテナ起動スクリプト）
- 修正理由とアプローチの簡潔な解説
- `--publish-socket` を使った新しい起動コマンドの例
- 動作確認の手順

## 5. 参考: 期待される変更イメージ
**Before** (`common.sh.template` 内):
```bash
mkdir -p ~/.config/herdr && \
ln -sf /home/pi/.rtk /home/pi/.config/rtk && \
pm2 start socat --name "herdr-socat" -- UNIX-LISTEN:/home/pi/.config/herdr/herdr.sock,fork,reuseaddr TCP:${HOST_IP}:9123
```

**After** (`container run` 呼び出し側に追加):
```bash
container run --publish-socket /path/on/host/herdr.sock:/home/pi/.config/herdr/herdr.sock ...
```
（`common.sh.template` からは socat/pm2 の行を削除し、mkdir は --publish-socket により自動作成されるか検討）
