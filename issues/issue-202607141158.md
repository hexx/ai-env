# 課題解決プロンプト: DockerfileにPythonとuvを導入する

## 1. 役割定義 (Persona)
あなたは高度なソフトウェアエンジニアおよびコンテナ/Dockerのエキスパートです。以下のコンテキストとゴールを基に、正確かつ効率的な修正/実装を行ってください。

## 2. 背景・前提条件 (Context)
- **現状発生している問題**: 現在の `Dockerfile` には Python ランタイムおよび Python パッケージマネージャーである `uv` が導入されていないため、Python アプリケーションの実行環境や依存関係管理を行えない。
- **再現手順**: リポジトリの `Dockerfile` を開き、Python がインストールされているか、および `uv` コマンドが利用可能かを確認する。
- **関連ファイル/コード**: `Dockerfile`（リポジトリルート）

## 3. 解決すべきゴール (Goal & Objective)
- [ ] ベースイメージとして Python が利用できるよう `Dockerfile` を構成する（Python 公式イメージの利用、または既存ベースへの Python インストール）
- [ ] Python 用高速パッケージマネージャー `uv` をインストールし、`uv` コマンドがコンテナ内で利用可能にする
- [ ] 既存のビルド/実行手順を壊さないよう、適切なバージョン指定とパス設定を行う

## 4. 期待する成果物 (Output Format)
- 修正が完了した `Dockerfile` 一式
- 修正理由とアプローチの簡潔な解説（ベースイメージの選定理由、`uv` のインストール手段など）
- `docker build` によるビルド成功、およびコンテナ内で `python --version` と `uv --version` が正しく実行できることの確認結果

## 5. 実行開始の合図
このプロンプトを理解したら、「タスクを開始します」と宣言し、直ちにステップ2の「関連ファイル」の解析から始めてください。

## 6. 実行・検証記録 (2026-07-14)

### 実施内容
- `Dockerfile`（ベース `node:24-trixie-slim`）のセクション1（apt インストール）に以下を追加:
  - `python3`, `python-is-python3`
  - `python-is-python3` により `python` コマンドが `python3` へ紐づき、`python --version` が動作する。
- 新セクション「1.5」を追加し、uv 公式インストールスクリプトを `UV_INSTALL_DIR=/usr/local/bin` で実行。
  - 全ユーザー（非root の `pi` ユーザー含む）の PATH 上に配置するため `/usr/local/bin` を指定。
  - 既存の Node.js 環境・実行手順には一切影響しない。
- **lean 化の追記**: 初回実装時は `python3-venv` / `python3-pip` も追加していたが、uv がパッケージ管理・仮想環境作成を自己完結して担うため、不要な `pip` / `venv` は削除。`python3` + `python-is-python3` + `uv` のみの構成とした。

### 検証結果
- **uv インストールロジック**: 一時ディレクトリで公式スクリプトを `UV_INSTALL_DIR` 指定で実行し、`uv` バイナリ（v0.11.28）が生成され、`uv --version` が正常動作することを確認。
- **Python パッケージ**: ホスト環境に python3 がないため apt インストールは直接検証不可。ただし指定パッケージは Debian trixie の標準パッケージであり妥当。
- **実ビルド (`docker build`)**: 本環境に Docker デーモン/CLI が存在しないため実行不可。ビルドは未検証。

### 残課題・注意
- コンテナランタイムが利用可能な環境で `docker build .` を実行し、`python --version` および `uv --version` の動作を最終確認することを推奨。
- astral.sh のスクリプト直接実行にはサプライチェーンリスクがある点は既存 Dockerfile の他スクリプトと同様にコメントで明記済み。
