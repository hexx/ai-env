# 課題解決プロンプト: RTK の再導入（PR #105 で削除した構成の完全復元＋公式 pi 連携）

## 1. 役割定義 (Persona)
あなたは ai-env（AI 開発用 Docker サンドボックス起動 CLI）と rtk（rtk-ai/rtk, "Rust Token Killer"）に精通したエンジニアです。下記の背景と決定事項に従い、正確かつ最小リスクで再導入を実装してください。

## 2. 背景・前提条件 (Context)

### 背景
- RTK はシェルコマンドの出力を圧縮して LLM のトークン消費を削減する CLI プロキシ。本サンドボックスに導入済みだったが、**PR #105（commit `6c094c5`）で全削除**された。
- 削除理由: rtk の出力圧縮・コマンド書き換えが **pull-request スキル実行時の AI を混乱させた**ため。
- 再導入理由: pull-request スキルが頑健化され、rtk 圧縮出力に耐えると判断されたため。目的はトークンコスト低減。
- **設計決定はすべて grill-with-docs セッション（2026-07-27）で確定済み。下記から逸脱しないこと。** 決定の背景は `docs/adr/0001-rtk-reintroduction.md` と `CONTEXT.md` を参照。

### 確定済みの決定事項（変更禁止）
1. **旧構成の完全復元**＋pi 拡張機能の追加。部分導入はしない。
2. **マウント二段構成を簡略化しない**: ホスト `~/.config/rtk` → コンテナ `/home/pi/.rtk` マウント＋起動時 symlink。`/home/pi/.config/rtk` への直接マウントへの変更は禁止（過去にトラブル歴あり・詳細は失念されているが、再現性が優先）。
3. **ホスト側ディレクトリの事前作成（mkdir 等）は追加しない**。ホストに `~/.config/rtk` が存在することを前提とする（既知の制約）。
4. **バイナリはバージョン固定しない**: 旧構成どおり master の install.sh を curl 実行。Dockerfile に herdr と同種のサプライチェーンリスクの注釈を追加すること。
5. **全プロファイル（pi-work / pi-private 両方）で有効**。プロファイルによるゲートはしない。
6. 拡張機能は手書きせず **rtk 公式の pi 連携**（`rtk init -g --agent pi`、tool_call 書き換え方式）を使う。`~/.pi` はホストからのボリュームマウントのため、Dockerfile に拡張機能を焼き込んでも無効化される点に注意。

### 復元対象（PR #105 の差分 = `git show 6c094c5` で確認できる削除箇所の逆適用）
- `Dockerfile`: herdr インストールの RUN 行にあった `&& curl -fsSL https://raw.githubusercontent.com/rtk-ai/rtk/refs/heads/master/install.sh | sh \` の復活（herdr 行と連結していた形式）。**加えて**、herdr の注釈コメントに倣い rtk も同種のサプライチェーンリスク（ダウンロードスクリプト直接実行・バージョン無固定）を負う旨のコメントを追記。
- `index-helpers.ts`: 定数 `const CONTAINER_RTK_CONFIG = "/home/pi/.rtk";`（`CONTAINER_PI_HOME` の次）と、`buildVolumeArgs` への `--volume=${home}/.config/rtk:${CONTAINER_RTK_CONFIG}` 行（`.pi` マウントの次）を復活。
- `templates/common.sh.template`: `ln -sf /home/pi/.rtk /home/pi/.config/rtk && \` 行（`mkdir -p ~/.config/herdr && \` の直後）を復活。
- `index.test.ts`: `buildVolumeArgs` のテストを 4→5 つへ戻す（テスト名・アサーションは `git show 6c094c5` の逆）。
- `.gitignore` の `.config/` エントリは #105 で追加されたものだが、ローカル生成物防止に有効なので**残す**（コメントの rtk 言及も実態に合うためそのまま）。

### 新規追加（旧構成には無かった要素）
- `templates/common.sh.template`: symlink 行の**後**（pm2 行より前）に、pi 向け公式連携のインストール行を追加:
  ```bash
  RTK_TELEMETRY_DISABLED=1 rtk init -g --agent pi && \
  ```
  - `RTK_TELEMETRY_DISABLED=1`: 非対話の起動スクリプトで telemetry 同意プロンプトが出ないための保険（rtk v0.44.0 以降で対応。common.sh は `set -euo pipefail` のため、プロンプトが出ると起動がハング/失敗する）。
  - 実装時に検証すること: (a) この行が非対話で完了すること、(b) 毎回起動で再実行して冪等であること（rtk は再実行によるアップグレードを公式にサポートしている）、(c) `rtk init` が RTK.md（エージェント向け説明文）も導入する場合、毎セッションのプロンプト負荷になるため `--hook-only` への変更を検討すること（トークン削減が目的なのに説明文でトークンを増やすのは本末転倒になりうる。RTK.md が小さい/有用なら既定のまま）。
  - `rtk init` はホストマウントされた `~/.pi/agent/extensions/` へ拡張機能を書く（ホスト側に永続化される。これは意図した動作）。
