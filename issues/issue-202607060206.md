# 課題解決プロンプト: DEEPSEEK_API_KEY をクレデンシャルとして追加

## 1. 役割定義 (Persona)
あなたは高度なソフトウェアエンジニアです。既存のコードベースに新しいクレデンシャル（API キー）を追加する作業を、既存のパターン（OPENCODE_API_KEY）に正確に倣って実施してください。

## 2. 背景・前提条件 (Context)
- **現状**: プロジェクトには `OPENCODE_API_KEY`、`OPENROUTER_API_KEY`、`LLM_API_KEY` など複数の API キーが `CREDENTIAL_SOURCES` に登録されており、macOS Keychain から動的取得 → コンテナの `--env` 引数として注入されている。
- **依頼内容**: これと同じ仕組みで `DEEPSEEK_API_KEY` を追加したい。DeepSeek API を使用するプロファイル向けに、macOS Keychain の `DEEPSEEK_API_KEY` エントリから値を取得し、コンテナに `--env=DEEPSEEK_API_KEY=...` として注入できるようにする。
- **既存の追加パターン**: `OPENCODE_API_KEY` が `CREDENTIAL_SOURCES` に登録されており、型・クレデンシャル取得・env 引数生成・テストのすべてで一貫して追加されている。

## 3. 解決すべきゴール (Goal & Objective)
- [ ] **CREDENTIAL_SOURCES に DEEPSEEK_API_KEY を追加** (`index-helpers.ts`)
  - `args: ["find-generic-password", "-s", "DEEPSEEK_API_KEY", "-w"]`
  - `file: "security"`
  - `name: "DEEPSEEK_API_KEY"`
  - アルファベット順で適切な位置に挿入すること（"D" は "G" より前なので `GH_TOKEN` の前に配置）
- [ ] **buildEnvArgs に DEEPSEEK_API_KEY の env 引数を追加** (`index-helpers.ts`)
  - `--env=DEEPSEEK_API_KEY=${params.credentials.DEEPSEEK_API_KEY ?? ""}` を追加
  - 他のクレデンシャルと同様にアルファベット順で配置
- [ ] **テストの sampleCredentials に DEEPSEEK_API_KEY を追加** (`index.test.ts`)
  - 適切なモック値（例: `"sk-ds-123"`）を追加
- [ ] **buildEnvArgs テストの env 引数カウントを更新** (`index.test.ts`)
  - 現在 12 個の `--env` 引数を期待しているテストを 13 個に更新
- [ ] **README.md のクレデンシャル一覧表を更新**
  - `DEEPSEEK_API_KEY` の行を macOS Keychain として追加
- [ ] **dist/index.js を再ビルド**
  - `npm run build` 等でビルドを実行（ビルドスクリプトの確認が必要）
- [ ] **既存のテストがすべてパスすることを確認** (`npm test`)

## 4. 期待する成果物 (Output Format)
- 修正が完了したコード（`index-helpers.ts`、`index.test.ts`、`README.md` の diff）
- 修正理由とアプローチの簡潔な解説
- `npm test` の実行結果（全テスト通過を確認）
- 再ビルド済みの `dist/index.js`

## 5. 実行開始の合図
このプロンプトを理解したら、「タスクを開始します」と宣言し、直ちに `CREDENTIAL_SOURCES` の解析から始めてください。
