# 課題解決プロンプト: BRAVE_SEARCH_API_KEYをfind-generic-passwordから取得し環境変数として渡す

## 1. 役割定義 (Persona)
あなたは高度なソフトウェアエンジニアおよび pi coding agent のコンテナ起動ランチャー
(`ai-env`) に精通したエキスパートです。以下のコンテキストとゴールを基に、正確かつ
最小リスクで修正/実装を行ってください。

## 2. 背景・前提条件 (Context)
- **現状発生している問題**:
  現在 `ai-env` は macOS Keychain (`security find-generic-password`) から複数の
  API キー/トークンを動的に取得し、コンテナ起動時に `--env=...` として注入している。
  しかし **`BRAVE_SEARCH_API_KEY` は取得対象にも注入対象にも含まれていない**。
  そのため、Brave Search 拡張機能 (`brave-search.ts`) がコンテナ内で
  `process.env.BRAVE_SEARCH_API_KEY` を参照しても、値が渡されておらず動作しない。
- **再現手順**:
  1. ホスト macOS の Keychain に `BRAVE_SEARCH_API_KEY` を登録してある状態で `ai-env` を実行。
  2. コンテナ内で `echo "$BRAVE_SEARCH_API_KEY"` を確認する。
  3. 現在は注入されていない（空）ため、Brave Search ツールが API 呼び出しに失敗する。
- **関連ファイル/コード**:
  - `/workspace/index-helpers.ts`
    - `CREDENTIAL_SOURCES` 配列（約 L60 付近）: `security find-generic-password -s <NAME> -w`
      形式で各クレデンシャルの取得定義を列挙。ここに `BRAVE_SEARCH_API_KEY` のエントリを追加する。
    - `Credentials` 型: `CREDENTIAL_SOURCES` から `name` をキーとして自動導出されるため、
      配列に追加するだけで型も自動拡張される。
    - `SECRET_ENV_PATTERN`（redactableNames）: `CREDENTIAL_SOURCES` の `name` 一覧を
      正規表現に組み込んでいるため、**配列への追加だけでログマスキングの対象にも自動で含まれる**。
    - `buildEnvArgs(params)`: コンテナへ渡す env リスト（現在 14 個）を組み立てている。
      末尾の `GH_TOKEN` 行の直後に `--env=BRAVE_SEARCH_API_KEY=${params.credentials.BRAVE_SEARCH_API_KEY ?? ""}`
      を追加する。これで注入対象リストは 15 個になる。
    - `loadCredentials(exec)` / `getCredential(file, args, exec)`: `CREDENTIAL_SOURCES` を
      巡回して取得するため、配列追加のみで取得フローに組み込まれる（ベストエフォート:
      取得失敗時は警告のみでコンテナ起動は継続）。
  - `/workspace/README.md`
    - 「クレデンシャル」の表（現在 `DEEPSEEK_API_KEY`, `XIAOMI_TOKEN_PLAN_SGP_API_KEY`,
      `OPENCODE_API_KEY`, `OPENROUTER_API_KEY`, `LLM_API_KEY`, `GH_TOKEN` を列挙）に
      `| \`BRAVE_SEARCH_API_KEY\` | macOS Keychain |` の行を追加し、仕様を同期する。
  - `/workspace/index.test.ts`
    - `buildEnvArgs` のテストで env 引数の数（現在 14 個）と個別の `--env=...` の期待値を
      検証しているため、追加に伴い期待値（14 → 15）および新しい env の検証を更新する。
    - `loadCredentials` / `CREDENTIAL_SOURCES` 関連のテストもソース追加に合わせて確認・更新する。

## 3. 解決すべきゴール (Goal & Objective)
- [ ] `index-helpers.ts` の `CREDENTIAL_SOURCES` に以下のエントリを追加する
      （`sort-keys` ルールに従い `args, file, name` のアルファベット順）:
      ```ts
      {
        args: ["find-generic-password", "-s", "BRAVE_SEARCH_API_KEY", "-w"],
        file: "security",
        name: "BRAVE_SEARCH_API_KEY",
      },
      ```
- [ ] `buildEnvArgs` の env リストに
      `--env=BRAVE_SEARCH_API_KEY=${params.credentials.BRAVE_SEARCH_API_KEY ?? ""}`
      を追加する。
- [ ] `SECRET_ENV_PATTERN` への取り込み（自動）を確認し、ログマスクが機能することを
      期待する（明示的な追加コードは不要）。
- [ ] `README.md` のクレデンシャル表に `BRAVE_SEARCH_API_KEY | macOS Keychain` を追加する。
- [ ] `index.test.ts` の env 引数数期待値（14 → 15）および関連テストを更新し、通ることを確認する。
- [ ] 既存の他クレデンシャル取得・注入フロー（`GH_TOKEN` 等）や、`buildEnvArgs` の
      呼び出し側（`runContainerCommand`）には影響を与えないこと。

## 6. 実行・検証記録 (2026-07-14)

### 実施内容
- **`/workspace/index-helpers.ts`**:
  - `CREDENTIAL_SOURCES` に `BRAVE_SEARCH_API_KEY` のエントリを追加（アルファベット順で先頭）。
    `security find-generic-password -s BRAVE_SEARCH_API_KEY -w` で Keychain から取得。
    これにより `Credentials` 型・`SECRET_ENV_PATTERN` のマスク対象・`loadCredentials` の
    取得ループのすべてに自動で組み込まれる（明示的追加コード不要）。
  - `buildEnvArgs` の env リスト末尾（`GH_TOKEN` の直後）に
    `--env=BRAVE_SEARCH_API_KEY=${params.credentials.BRAVE_SEARCH_API_KEY ?? ""}` を追加。
    注入対象は 14 個 → 15 個になった。
- **`/workspace/README.md`**: クレデンシャル表に
  `| \`BRAVE_SEARCH_API_KEY\` | macOS Keychain |` を追加し仕様を同期。
- **`/workspace/index.test.ts`**:
  - `sampleCredentials()` に `BRAVE_SEARCH_API_KEY` を追加。
  - `buildEnvArgs` の env 引数数テストを 14 → 15 に更新、タイトルの「全 12 個」も
    「全 15 個」に修正、かつ `BRAVE_SEARCH_API_KEY` が注入されることを検証する新テストを追加。
  - `loadCredentials` の取得順（7 件になった）に合わせモック応答・アサーションを更新、
    空クレデンシャル（ベストエフォート）テストの期待値も並び順変更に追随。
  - `redactSecrets` で `BRAVE_SEARCH_API_KEY` が `***` にマスクされることを検証する新テストを追加。

### 検証結果
- `npm test`: **81 件すべてパス**（fail 0）。
  - 新規テスト `BRAVE_SEARCH_API_KEY が env 引数として注入される` が
    `--env=BRAVE_SEARCH_API_KEY=brave-111` を正しく出力することを確認。
  - 新規テスト `CREDENTIAL_SOURCES 由来の BRAVE_SEARCH_API_KEY も *** に置き換える` が
    マスク対象に自動含まれることを確認。
- `npx oxlint`: クリーン（warning/error なし）。`sort-keys` ルール等に抵触せず。
- `npm run build`（esbuild バンドル）: 成功（`dist/index.js` 生成）。
- `npx tsc --noEmit`: 本変更起因の型エラーなし（既存の tsconfig 非推奨警告のみ）。

### 補足
- コンテナ起動時の `container ...` コマンドラインは `redactSecrets` により stderr に
  ダンプされる前にマスクされるため、`BRAVE_SEARCH_API_KEY` の値がログに漏れない。
- ホスト macOS の Keychain に `BRAVE_SEARCH_API_KEY` が未登録の場合は `loadCredentials` が
  ベストエフォートで警告のみ出力し、コンテナ起動は継続（空文字が注入される）する。
